- Built from the working changes on `master` based on `9791d63`, including previously untracked native source/resources. Version `1.0.4`, code `5`, package `com.firesky.app`.
- Original upload key retained (alias `upload`); no signing credentials committed.
- Published as **1.0.4 native internal** to track `4701618212420516910`. Play Console verified **Active** and **Available to internal testers**.
- AAB: `android/build/play-release-1.0.4/FireSky-1.0.4-native.aab`, 26,119,727 bytes.

## Backend

- Verified schema absence, then applied `0006_reactions_and_viewpoint_photos.sql` to remote D1 before deploying the new Functions.
- Primary Pages deployment: https://2a27d564.fireskychase.pages.dev, production https://fireskychase.pages.dev.
- Secondary Pages deployment: https://591f66a4.firesky.pages.dev, production https://firesky.pages.dev.
- Fixed omitted photo fields from old clients clearing current photo references; explicit null still removes them.
- Real signup verification exposed the production native PBKDF2 limit (100,000 vs the configured 180,000 iterations). Switched to pinned `@noble/hashes` PBKDF2-SHA256, retaining salt, output format and the 180,000 iteration work factor. Node-compatible crypto had the same production limit and was not retained.
